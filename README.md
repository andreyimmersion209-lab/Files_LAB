# Лабораторная работа № 7. Структуры и работа с файлами

## Автор

Хан Кирилл, ПИ-261. Вариант 26.

## Цель и задача

Научиться хранить связанные поля в структуре, обрабатывать вектор записей функциями, проверять текстовый файл и записывать отчёт.

Файл содержит автомобили: производитель, модель, объём двигателя и стоимость. Программа выводит все машины заданного производителя и их среднюю стоимость. Среди **всех** автомобилей, независимо от производителя, находит машину с самым большим объёмом двигателя. При равенстве объёмов выбирается первая запись файла.

## Формат файла

Каждая строка описывает один автомобиль:

```text
manufacturer;model;engineVolume;price
```

Это описание порядка полей: строку заголовка в файл добавлять не нужно. Число записей в начале файла тоже не указывается. Пример `input.txt` уже подготовлен:

```text
Toyota;Corolla;1.6;20000
Ford;Mustang GT;5.0;60000
Toyota;Camry;2.5;30000
Volkswagen;Golf;1.4;18000
Land Rover;Range Rover;5.0;95000
```

Используются `struct Car` и `vector<Car>`. Производитель и модель имеют тип `string`, объём и стоимость — `double`. В этой реализации объём измеряется в литрах, а цены задаются в одной общей денежной единице. Пример содержит условные учебные цены.

Правила входных данных:

- От 0 до 100 записей. Пустой файл разрешён.
- Ровно четыре поля, разделённых `;`. Пустая строка между записями — ошибка.
- Производитель и модель — непустой печатный ASCII-текст, содержащий хотя бы один символ, отличный от пробела. Внутри названия пробелы разрешены; `;`, управляющие символы и кириллица запрещены.
- Названия сравниваются точно, с учётом регистра и пробелов. Пробелы по краям автоматически не удаляются.
- Для проверки смысловой корректности приняты объём двигателя строго больше нуля и стоимость не меньше нуля. Нулевая цена допустима. Других ограничений на эти значения методичка варианта не задаёт.
- Числа должны быть конечными и полностью распознаваться: `2.5x`, `1,6`, пустое число, `NaN` и бесконечность недопустимы. Дробная часть отделяется точкой, допустима экспоненциальная запись. Пробелы вокруг числа допустимы.
- Файл сохраняется как ASCII или UTF-8 **без BOM**, с окончаниями строк LF или CRLF. Один завершающий перевод строки допустим, дополнительная пустая строка — нет.

## Запуск

Создайте пустой проект C++ в Visual Studio и добавьте `Lab7Variant26.cpp`. Выберите стандарт C++11 или новее. В проекте должна быть одна функция `main`. Если включены предкомпилированные заголовки, отключите их для этого файла. Добавьте `input.txt` как существующий элемент проекта.

Запустите без отладки через Ctrl+F5 и введите **три отдельные строки**, без кавычек:

1. Путь входного файла.
2. Путь выходного файла.
3. Производитель для поиска.

Первую проверку удобно выполнить с абсолютными путями. Например, после распаковки в `C:\Labs\Lab7`:

```text
C:\Labs\Lab7\input.txt
C:\Labs\Lab7\report.txt
Toyota
```

Замените папку на свою. Каталог для выходного файла должен уже существовать. Для простоты используйте пути из латинских букв. Если рабочая папка процесса совпадает с папкой данных, можно ввести относительные пути:

```text
input.txt
report.txt
Toyota
```

Относительный путь отсчитывается от **рабочей папки запущенной программы**, а не обязательно от папки `.cpp` или `.exe`. В Visual Studio её можно указать в свойствах проекта: отладка → рабочий каталог. Добавление файла в проект само по себе не меняет рабочую папку.

Входной и выходной файлы должны быть разными. Совпадающие строки путей отклоняются; не указывайте один файл двумя разными способами, например `input.txt` и `./input.txt`. При успешном запуске существующий выходной файл перезаписывается.

## Результат примера

На экране и в `report.txt` получится один и тот же текст:

```text
Manufacturer: Toyota
Cars:
Toyota;Corolla;1.6;20000
Toyota;Camry;2.5;30000
Count: 2
Average price: 25000
Largest engine (all cars):
Ford;Mustang GT;5;60000
```

У Land Rover тоже объём 5, но Ford находится раньше. Он попадает в общий максимум, хотя запрос выполнен для Toyota. Порядок выбранных автомобилей совпадает с порядком файла. Числа выводятся с обычной точностью потока, поэтому могут округляться; в отчёт попадают числовые значения, а не исходное написание `5.0`.

При отсутствии совпадений список заменяется на `EMPTY`, количество равно 0, средняя стоимость — `NONE`. При этом общий максимум по непустому файлу всё равно выводится. Для полностью пустого файла общий максимум тоже равен `NONE`.

Приглашения ко вводу не печатаются, чтобы успешный вывод экрана точно совпадал с отчётом. Сначала программа ждёт три строки ввода.

## Сообщения об ошибках

| Сообщение | Причина |
| --- | --- |
| `ERROR parameters` | Не введены три строки или один из путей пуст. |
| `ERROR paths` | Введены одинаковые строки входного и выходного пути. |
| `ERROR query` | Неправильное название производителя в запросе. |
| `ERROR input` | Входной файл не удалось открыть. |
| `ERROR line N` | Ошибка в строке N или обнаружена 101-я запись. |
| `ERROR read` | Сбой чтения входного файла. |
| `ERROR calculation` | Сумма конечных цен переполнила диапазон double. |
| `ERROR output` | Выходной файл не удалось открыть для записи. |
| `ERROR write` | Ошибка при записи, сбросе буфера или закрытии выходного файла. |

При неправильном вводе или исходном файле отчёт не создаётся и существующий выходной файл не меняется. При сбое самой записи выходной файл может оказаться неполным, но успешный отчёт на экран не выводится. Пустой файл и отсутствие совпадений ошибками не являются.
